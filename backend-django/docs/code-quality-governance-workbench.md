# 代码问题治理工作台产品与实现说明

## 定位

代码问题治理是 `agent_tools` 下完全独立的治理工作台，不复用项目管理或既有扫描模块。项目、责任田和项目责任田关系共同构成治理上下文，首屏优先展示风险、待办和扫描异常，基础资料维护从属于上下文详情而不是孤立的 CRUD 页面。

## 首期范围

- 治理工作台：全局指标、我的审批待办、扫描异常、高风险项目和责任田排行。
- 项目中心：目录筛选、项目 360° 概览、引导式创建、停用但保留历史。
- 责任田中心：目录筛选、多个看护人、责任田 360° 概览和看护人审计。
- 项目 × 责任田矩阵：单个/批量关联、停用、风险单元格和关系聚合数据。
- 扫描接入中心：必须绑定有效关系，保留原始报告，解析失败不产生半成品问题。
- 问题中心：稳定身份归并、命中历史、证据/identity 展开、批量屏蔽申请。
- 审核中心：待我审批、我的申请、全部申请、审批和审计日志。

## 非目标

- 不引入仓库、分支、子项目、组织树或复杂角色体系。
- 不复用 `project_manager`、`code_scan` 的模型、接口、页面或服务。
- 不实现复杂审批编排、屏蔽到期、自动推荐和异步 Webhook。

## 领域约束

1. 项目和责任田均为本模块独立维护的简单主数据。
2. 一个项目与一个责任田最多有一条关系；关系停用不删除历史报告、问题和申请。
3. 扫描接入必须使用有效关系；`complete=false` 仍然成功入库并展示未完成提示。
4. 稳定身份优先使用 `identity.issue_key`、legacy fingerprint、fingerprint，最后使用平台回退身份。
5. 责任田看护人是默认审批人候选；申请人也可指定任意有效系统用户，审批时仅校验用户有效。
6. 屏蔽审批在一个事务中更新申请、问题状态和审计日志。

## 验收标准

- 进入页面先看到工作台而不是主数据表格。
- 项目/责任田详情可以直接进入问题、扫描和审批上下文。
- 矩阵支持关联、停用和批量关联，停用关系禁止新扫描接入。
- 同一项目责任田稳定身份跨报告只创建一个问题，每次报告创建一个命中记录。
- 解析失败的报告可查询并带错误信息，不创建问题命中。
- 屏蔽申请、审批状态和日志始终一致，已处理申请不可重复审批。

## 实施顺序

1. 扩展独立模型、聚合字段、看护人和迁移兼容。
2. 增加工作台、项目/责任田概览、矩阵和新接入接口。
3. 重写单页面内部导航及各工作区组件，保持 Vben/Element Plus 管理台主题。
4. 执行 Python 编译、Django 检查、专项测试和前端类型检查。
