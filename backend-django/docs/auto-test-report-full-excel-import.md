# Auto Test Report 一站式 Excel 导入

## 问题与目标

旧流程要求用户先选择一个车型，再上传该车型的用例 Excel。多车型场景需要重复下载、选择和上传，容易漏导或选错车型。

新流程按当前领域下载模板，一个文件可以同时维护多个版本、车型和用例。页面上传时不再依赖车型筛选条件，旧的单车型 JSON 和 Excel 接口继续保留用于兼容已有调用方。

## 模板字段

- 座舱 MCU：版本名称、版本标识、车型名称、车型编号、CDC平台、执行机器、用例编号、用例名称、备注。
- 座舱 SOC：在座舱 MCU 字段基础上增加模块。
- 车控：版本名称、版本标识、车型名称、车型编号、执行机器、VIU编号、用例编号、用例名称、备注，不配置 CDC 平台。

一份文件只能导入当前选择的一个领域。版本和车型字段始终必填；用例编号和用例名称可以同时留空，此时该行只创建或更新平台和车型。两者只填写一个会作为错误行返回。

## 匹配与更新规则

- 平台按版本标识匹配，存在时更新模板内的版本名称，不存在时创建。
- 车型按车型编号匹配，存在时更新所属版本、车型名称、CDC 平台和执行机器，不存在时创建。
- 座舱 MCU 和座舱 SOC 用例按车型与用例编号匹配；车控用例按车型、VIU 编号与用例编号匹配。
- SOC 的有用例行必须填写模块，车控的有用例行必须填写合法 VIU 编号。
- 车控 VIU 配置采用增量合并，避免导入部分用例时破坏车型已有的 VIU 和存量用例。
- 未出现在文件中的存量用例不删除、不停用。

## 错误处理

导入前先检查同一版本标识、车型编号或用例唯一键是否在文件中出现互相矛盾的配置。冲突涉及的所有行都会被拒绝，不按行顺序覆盖。

合法行和错误行可以并存。每一行在独立数据库保存点内处理；该行任一层级失败时，平台、车型和用例变更一起回滚，其他合法行继续导入。响应会返回平台、车型、用例的新增或更新数量、纯配置行数量以及 Excel 实际错误行号。

## 接口

- `GET /api/auto-test-report/test-cases/template?domain=...`：下载当前领域的一站式模板。
- `POST /api/auto-test-report/test-cases/import-full-excel`：表单上传 `domain` 和 `file`。
- `POST /api/auto-test-report/test-cases/import`：保留原单车型 JSON 导入。
- `POST /api/auto-test-report/test-cases/import-excel`：保留原单车型 Excel 导入。

## 验收标准

- 无需选择车型即可一次导入多个版本、车型和用例。
- 纯平台车型配置行可以成功写入。
- 重复导入只更新匹配记录，不生成重复数据，也不删除未包含的旧用例。
- 错误提示包含准确 Excel 行号，错误行不会留下半成品数据。
