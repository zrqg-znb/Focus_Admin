# 漏合风险页表头筛选改造说明

## 背景

漏合风险页原本把列表筛选条件集中放在页面顶部。随着筛选项增多，列表区域被压缩，用户在查看风险明细时需要频繁把视线从表头和数据行拉回到顶部表单，扫描效率较低。

本次改造将风险列表筛选迁移到 `zq-table` 表头，保留顶部全局操作和视图切换，把筛选动作尽量放回对应列语义附近。

## 交互决策

- `风险列表` 使用表头筛选。
- `PL组看板` 使用独立的简化筛选区。
- 列表表头筛选不再直接驱动看板查询。
- 页面级不再保留独立的“查询”按钮。

## 表头筛选映射

- `漏合CR`：关键词，支持标题 / Change Key / 代码库关键词。
- `状态`：状态筛选。
- `代码库`、`组织`：共用组织/代码库级联多选范围。
- `创建人`：姓名 / 工号。
- `PL组`：PL组多选。
- `主干分支`、`发布分支`：分支名输入筛选。
- `主干合入时间`、`识别时间`：时间范围筛选。

所有筛选通过 `Filter` 图标触发下拉面板；输入类支持回车应用；选择器、级联和时间范围在变更或清空后自动刷新列表。

## 看板筛选边界

`PL组看板` 只保留少量真正需要的全局条件：

- 组织/代码库
- PL组
- 合入时间

这样可以避免用户在切到看板后，看不到列表表头筛选，却仍然被其隐式影响统计结果。

## 开发约束

- 不改后端漏合风险筛选接口字段，只改前端承载方式。
- 组织/代码库筛选继续沿用现有 Cascader 并集语义。
- 顶部保留 `刷新任务`、`手动同步`、视图切换和最近任务摘要，作为全局操作区。
