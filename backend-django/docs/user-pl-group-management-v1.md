# 用户管理页 PL 组改造 v1

## 问题与目标

用户管理页需要直接查看和维护用户所属 PL 组，减少在 PL 组管理页来回切换的成本。列表筛选必须和分页总数一致，因此 PL 组筛选下沉到后端用户列表接口。

目标用户是系统管理员和 PL 资源组维护人员。

## 范围

- 用户列表新增“所属 PL 组”列。
- 用户列表顶部新增 PL 组多选筛选。
- 用户编辑抽屉新增 PL 组多选编辑。
- 用户列表表格从 VXE Grid 迁移为 `zq-table`。
- 不新增数据库字段，复用 `PlGroup.members` 和 `User.pl_groups` 多对多关系。

不包含 PL 组的创建、负责人变更和成员批量导入能力，这些仍在 PL 组管理页维护。

## API 与页面映射

- `GET /api/core/user`：新增 `pl_group_ids[]` 查询参数，按用户所属 PL 组多选筛选并去重。
- `POST /api/core/user`、`PUT /api/core/user/{user_id}`、`PATCH /api/core/user/{user_id}`：支持 `pl_group_ids`，用于设置用户所属 PL 组。
- 用户输出新增 `pl_groups`、`pl_group_ids`、`pl_group_names`，供列表展示和编辑抽屉回填。
- `/system/user` 页面使用 `GET /api/core/pl/all` 加载启用 PL 组作为筛选和编辑选项。

## 设计方向

保持内部管理后台风格：表格优先、信息密度适中、PL 组用紧凑标签展示，编辑入口仍放在用户抽屉内，避免新增页面层级。

## 验收标准

- 用户列表能展示每个用户所属的全部 PL 组。
- PL 组筛选支持多选，分页总数不因用户属于多个组而重复。
- 编辑用户保存 PL 组后，列表刷新并展示最新归属。
- 用户作为某个 PL 组负责人时，后端始终保留其负责人所在组的成员关系。
- 用户页迁移到 `zq-table` 后，创建、编辑、删除、批量删除、重置密码仍可用。

## 风险

- 历史禁用 PL 组仍会在用户归属中展示，但不会作为筛选和编辑选项出现。
- zq-table 与 VXE Grid 的列配置和选择事件不同，迁移后需要重点验证选择、操作列和自定义单元格。
