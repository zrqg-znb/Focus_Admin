# Project Manager 发布计划管理 V1

## 背景

项目配置需要记录每个项目的发布计划。一个项目可能存在多个分支，每个分支也可能有多个发布日期、版本类型、平台和车型组合。配置入口应放在新增/编辑项目流程中，看板页负责跨项目展示。

## 范围

- 在项目新增/编辑时维护发布计划。
- 支持多分支、多发布计划明细。
- 车控发布平台使用 IDVP 平台，座舱发布平台使用 CDC 平台。
- 发布计划字段限定为：分支名、发布日期、版本类型、平台、车型；版本类型保存为可直接填写的文本。
- 发布车型以计划内字符串数组保存。
- 新增发布计划看板，以“项目主行 + 展开分支明细”的高密度结构展示和筛选发布信息。

## API 与页面

- `ProjectCreateSchema` / `ProjectUpdateSchema` 新增 `release_plans`，保存策略为全量替换。
- `ProjectOut.release_plans` 返回项目下所有发布计划，按分支、发布日期、排序稳定排列。
- `GET /api/project-manager/release-plans/` 分页返回发布计划明细，保留给普通明细列表复用。
- `GET /api/project-manager/release-plans/project-board` 按项目聚合返回看板数据，`scenario` 必填且只支持 `vehicle` / `cockpit`，分页按项目计算。
- 前端页面：`/project-manager/release-plan`，组件 `/project-manager/release-plan/index`。
- 页面顶部提供车控域/座舱域二选一切换，并展示未来周发布数量趋势、版本类型周趋势。
- 主表一行一个项目，项目行展示项目/编码、经理、分支数、计划数、最近发布、版本类型、平台和车型摘要；展开区展示分支名、发布日期、版本类型、平台、车型，同分支多条计划合并分支名单元格。
- 项目、分支、发布日期、版本类型、平台、车型筛选均放在 zq-table 表头过滤器中，筛选变更后自动刷新。

## 验收标准

- 新建项目时可保存多个分支和多条发布计划。
- 编辑项目时可回显、删除、替换发布计划。
- 车控计划必须选择 IDVP 平台；座舱计划必须选择 CDC 平台。
- 每条计划必须填写分支名、发布日期、版本类型、发布车型。
- 看板默认进入车控域，可切换座舱域；不提供“全部”视图。
- 看板可按日期范围、项目/分支关键字、版本类型、平台、车型筛选，且分页不拆分同一个项目下的发布计划。
