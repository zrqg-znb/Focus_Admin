# 需求中心模块

需求中心模块 (`requirement_center`) 是系统内负责项目需求全生命周期管理的核心业务模块。它提供了从需求录入、分解、追踪到多维看板展示的闭环管理能力。

## 架构概览

### 核心模型与设计

需求中心采用了层级化的需求结构，以支持复杂产品的敏捷迭代与需求拆解：

- **Requirement (需求实体)**：需求的抽象表示，支持多级父子关系（如：Epic -> Feature -> Story -> Task）。
- **状态流转 (Status)**：管理需求从新建、规划中、开发中、测试中到已发布的状态流转。
- **关联关系**：支持需求与项目 (Project)、迭代 (Iteration)、责任人 (Owner)、验证人员等多维度的关联。

## 核心功能

1. **需求层级管理**：
   - 支持创建和维护父子需求关系，通过 `TreeTable` 清晰展示需求拆解脉络。
   - 父需求的状态或进度可由子需求的完成情况汇总驱动。
2. **看板与流转 (Board)**：
   - 提供敏捷开发常用的 Kanban 视图，支持拖拽改变需求状态。
   - 自定义列和流转规则，贴合不同团队的敏捷流程。
3. **迭代规划**：
   - 与 `project_manager` 模块协同，将需求指派至特定迭代。
   - 跟踪每个迭代内需求的承诺量与交付率。
4. **多维大盘与报表 (Dashboard)**：
   - 需求燃尽图、状态分布饼图、各责任人负载情况统计。
   - 通过图表直观了解项目当前的范围蔓延风险和交付健康度。

## API 接口与服务

- `/api/requirement-center/requirements`：需求的基础 CRUD 接口。
- `/api/requirement-center/requirements/tree`：获取特定项目或迭代下的树状结构需求列表。
- `/api/requirement-center/requirements/board`：看板数据的获取与卡片拖拽后的状态更新。
- `/api/requirement-center/dashboard`：用于统计看板的聚合数据。

## 使用场景

- 产品经理在项目启动阶段录入宏观特性（Epic/Feature），并逐级向下拆解为用户故事（Story）。
- 研发团队在迭代计划会议上，将用户故事认领并分配给具体开发人员，进入 Kanban 追踪。
- 项目管理者和业务方通过需求大盘实时查看迭代进度和交付物范围，保障项目的按期高质量交付。
