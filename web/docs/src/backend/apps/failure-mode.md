# 故障模式模块

故障模式模块 (`failure_mode`) 是为了管理、追踪和分析系统或产品中潜在故障及其影响而设计的核心业务模块，涵盖了故障模式的定义、流程化管理及关联产品/子系统的全生命周期追踪。

## 架构概览

### 核心设计

该模块采用配置驱动与工作流驱动结合的设计，主要包含以下子领域：

- **Failure Mode (故障模式)**：核心实体，记录故障的类型、表现、原因和影响范围。
- **Workflow (工作流)**：为故障模式的处理和状态流转提供流程引擎支持，支持多节点的流转与任务分配。
- **Master Data (主数据)**：包括产品线、基线、子系统等基础配置，为故障模式提供层级化、结构化的分类依据。
- **Statistics (统计分析)**：对不同产品、基线及子系统的故障模式数据进行聚合和可视化。

## 核心功能

1. **主数据配置与关联**：
   - 支持层级化的产品线和基线配置。
   - 子系统配置：支持系统到子系统、组件的层级划分，故障模式可以挂载到具体的硬件/软件组件上。
2. **故障模式定义与维护**：
   - 记录具体的故障现象、根本原因分析、严重程度（Severity）、发生频度（Occurrence）和可探测度（Detection），从而计算风险优先数（RPN）。
   - 支持字符串列表编辑器及关系图谱展示（Insight Drawer）。
3. **工作流管理**：
   - 故障模式的处理任务分配给特定角色或处理人。
   - 状态流转（如：新建 -> 分析中 -> 验证中 -> 已关闭）。
   - 任务交接与落地配置（Landing Config Drawer），确保修复措施在后续版本中得以落实。
4. **统计与大盘**：
   - 提供柱状图、饼图等多维度报表，展示各子系统故障分布、各基线高优风险趋势。

## API 接口与通信

- `/api/failure-mode/modes`：故障模式条目的增删改查。
- `/api/failure-mode/workflow`：工作流任务流转、状态更新及责任人分配。
- `/api/failure-mode/config`：子系统、产品线、角色等主数据的配置。
- `/api/failure-mode/statistics`：用于 Dashboard 的聚合数据接口。

## 使用场景

- 硬件或系统工程师在产品设计初期进行 FMEA（失效模式与影响分析），记录和评估潜在故障。
- 质量保障团队在产品测试和客诉阶段，追踪并录入新发现的故障模式。
- 项目管理者通过大盘了解各子系统的薄弱环节，推动研发团队对高风险模块进行重构或增加冗余设计。
